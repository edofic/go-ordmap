Allocation Notes

  • Direct range use such as for k, v := range tree.All() remains 0 B/op, 0 allocs/op.
  • Escape analysis says returned iterator closures can escape when the iter.Seq2 value is materialized; this is expected for the current API.
  • Construction benchmark confirms storing tree.All() costs 24 B/op, 1 alloc/op.
  • The explicit traversal stack itself does not escape: escape analysis reports append(stack, finger) does not escape.
  • Allocation-reducing changes are considered keeper-worthy even when CPU time is neutral or noisy.

Current Assessment

The AVL implementation remains the public API and still satisfies persistent snapshot behavior by closing iterators over immutable roots. The high-value gains came from removing recursive iterator overhead and avoiding work on missing deletes. Existing random lookups and min/max access are already small enough that recent micro-experiments were dominated by noise.

Next promising targets are write-path allocations for successful insert/remove and deeper comparison with the experimental B-tree, but those should be evaluated carefully because earlier B-tree benchmarks include key allocation artifacts.
